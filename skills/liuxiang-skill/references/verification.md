# 外部核验

核验只有用户提出要求时执行，当前宿主需要有可用的联网检索工具。脚本不提供搜索引擎，也不单独调用另一个模型。

1. 执行 `verify-prepare URL` 读取原文和候选疑点。
2. 选择1至6条可查证说法，把 `{"claims":["说法一","说法二"]}` 写入临时 JSON 文件，再执行 `verify-prepare URL --file CLAIMS_FILE`，取得 token 和 id。
3. 使用宿主的实际联网工具查找原始发布方、官方文档及适当的独立证据。逐项记录真实查询词，区分“支持”“矛盾”“未确认”。关联主题相同不等于证据支持这个说法；搜索没有结果不证明说法错误。
4. 将以下格式写入临时文件，执行 `verify-save --file RESULTS_FILE`。必须提交本次全部 id，token 只能成功保存一次。

```json
{
  "token": "使用 prepare 真实返回的 token",
  "results": [{
    "id": "1",
    "verdict": "未确认",
    "reason": "没有取得可以直接支持该说法的原始证据。",
    "queries": ["实际使用的查询词"],
    "evidence": []
  }]
}
```

支持/矛盾结论必须提供1至3条 evidence，每条为：

```json
{"url":"https://example.org/source", "title":"来源标题", "excerpt":"从证据网页实际读取并复制的短原文"}
```

短引文须16至160字符，最多25个以空格分隔的词；避免累计引用同一来源过多内容。脚本实际重新抓取网页并核对短引文，登记获取时间和页面摘要哈希。脚本验证引文存在，不自动证明逻辑蕴含关系，结论仍需宿主判断。

页面 403、登录、验证码、JavaScript 渲染或短引文无法再次读取时，该项用未确认，理由里写实际限制，可保留查询词及可访问证据。不要绕过校验或编造引文以提高状态。

所有选定说法有支持或矛盾结论：已核验；部分有结论：部分核验；全部未确认：未核验。这个状态只覆盖本次选定范围，矛盾也是核验取得的结论。查证期间正文被修改时停止保存，重新准备请求。
